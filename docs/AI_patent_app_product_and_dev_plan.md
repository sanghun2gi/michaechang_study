# PART A. 제품화 — 어떻게 팔 것인가

## A-1. 제품 포지셔닝

### 한 줄 정의 (판매용)

> "발명 아이디어를 넣으면, 등록 가능성을 진단하고 명세서·청구항 초안과
> 가상 거절이유(OA)까지 만들어 출원 준비 시간을 줄여 주는 AI 특허 비서.
> 단, 최종 판단은 변리사가 합니다."

### 핵심 판매 메시지 3가지

1. **시간 절약** — 명세서·청구항 초안과 선행기술 정리를 AI가 끌어올려, 사람이 처음부터 쓰는 시간을 줄인다.
2. **거절 사전 예방** — 출원 전에 가상 거절이유와 약점을 보여주어, 비싼 거절·재출원을 줄인다.
3. **추적·책임** — 모든 AI 판단의 근거가 원장에 남아, 변리사·기업이 믿고 검토할 수 있다.

### 반드시 지켜야 할 법적 경계 (판매·UI 공통)

> 이건 마케팅 문구이자 법적 방어선이다. 모든 화면·약관·랜딩에 일관되게 표기.

- "특허등록을 보장하지 않습니다."
- "본 서비스는 법률 자문이 아니며, 변리사·변호사의 검토를 대체하지 않습니다."
- "AI 산출물은 초안·참고자료이며, 최종 출원 판단은 사용자/전문가의 책임입니다."

이 경계는 **무자격 법률서비스(변리사법) 리스크**를 피하기 위한 것이기도 하다.
"AI가 출원해 준다/등록시켜 준다"는 표현은 절대 쓰지 않는다.
"출원 준비를 돕는다 / 초안을 만든다 / 진단한다"로만 표현한다.

## A-3. 가격·과금 설계 시 고려사항

1. **AI 비용이 변동비**다. 발명 1건 처리에 드는 LLM 토큰 비용을 측정해
   플랜별 사용량 한도(크레딧)를 설계한다. 무제한은 위험.
2. **보안등급 S(Private LLM)** 는 별도 비용 라인이다. Enterprise 전용·추가 과금.
3. **연동(KIPRIS Plus 등) API 비용**도 변동비 → Pro 이상에서만 제공하거나 종량.
4. 무료 체험은 "발명 1건, 진단까지만" 으로 제한(명세서 초안은 유료 전환 유인).

## A-4. 제품화를 위해 v5.0에 보완할 점

WORKFLOW v5.0은 기능 설계는 완벽하지만, **판매 가능한 제품**이 되려면 아래가 추가로 필요하다.

### (1) 온보딩·신뢰 확보 레이어

- 첫 사용자가 "이게 믿을 만한가"를 5분 안에 느끼게 하는 샘플 발명 데모
- 변리사 검토 마크(이 초안은 변리사 검토 전/후 표시)
- 결과물에 항상 신뢰구간·근거를 함께 표시(STEP 27 R2와 연결)

### (2) 결제·구독·사용량 관리

- 플랜 업/다운그레이드, 크레딧 잔량, 사용량 대시보드
- 결제는 직접 카드정보를 다루지 말고 PG/Stripe 등 외부 결제 위탁(보안·PCI 회피)

### (3) 데이터·보안·규정 (판매 신뢰의 핵심)

- 발명정보는 영업비밀이다. **암호화 저장, 테넌트 격리, 접근 로그**는 필수 판매 요건.
- 보안등급 S 데이터의 외부 모델 비전송을 **제품 기능이자 세일즈 포인트**로.
- 약관·개인정보처리방침·데이터 처리 위탁 고지 문서 세트.

### (4) 협업·승인 워크플로우 (Pro/Enterprise 차별화)

- 고객이 입력 → 변리사가 검토·코멘트 → 승인 → 출원 패키지 확정의 역할 흐름
- STEP 24B Human Authority Gate를 그대로 제품의 승인 기능으로 구현

### (5) 책임 한계·면책 (사업 생존 직결)

- 약관에 AI 산출물 면책, 등록 비보장, 법률자문 아님을 명시
- 잘못된 초안으로 인한 손해 배상 한계 설정 (법무 검토 필수 항목)

## B-1. 기술 스택 (확정)

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | **Next.js 14+ (App Router)** | 풀스택 한 코드베이스, API Routes로 백엔드 겸용 |
| 언어 | **TypeScript** | 타입 안정성, Claude Code가 안전하게 리팩터링 |
| UI | React + Tailwind CSS + shadcn/ui | 대시보드 UI 빠르게 구성 |
| DB | PostgreSQL (Prisma ORM) | 관계형 데이터(발명·청구항·Evidence·원장)에 적합 |
| 인증 | NextAuth.js (또는 Clerk) | SSO·역할기반 권한(Enterprise) 확장 용이 |
| AI | Anthropic API (서버 사이드 호출) | Agent 로직은 반드시 서버에서 (키 노출 방지) |
| 결제 | Stripe | 구독·크레딧 과금 위탁 |
| 배포 | Vercel (초기) → 필요시 자체 인프라 | Next.js 친화 |

> **보안 원칙:** AI API 키와 Agent 프롬프트는 절대 클라이언트로 보내지 않는다.
> 모든 Agent 호출은 Next.js의 서버(Route Handler / Server Action)에서만 실행한다.

## B-2. 데이터 모델 (핵심 테이블)

WORKFLOW의 산출물이 곧 DB 스키마다. Prisma 기준 핵심 엔티티:

```
User            사용자 (역할: owner / attorney / member)
Organization    조직 (테넌트 격리 단위, 보안등급 정책)
Project         프로젝트 (보안등급 S/A/B/C)
Invention       발명 (STEP 1 입력)
StructureCard   발명 구조화 카드 (STEP 3)
Evidence        선행기술 근거 (STEP 6 스키마 그대로)
Claim           청구항 (Ladder 단계, 축, 부모-자식)
ClaimElement    청구항 구성요소 (All Elements Matrix 연결)
Specification   명세서 (섹션별)
OASimulation    가상 거절이유 (STEP 21)
LedgerRecord    Provenance Ledger (STEP 0B — 모든 AI 판단 추적)
ReviewApproval  Human Authority Gate 승인 이력 (STEP 24B)
Subscription    구독·크레딧·사용량
```

> **설계 팁:** `LedgerRecord` 를 처음부터 넣어라. 나중에 추가하면 모든 Agent 호출
> 코드를 다 고쳐야 한다. AI 판단 함수가 항상 원장에 기록을 남기도록 래핑한다.

## B-3. 개발 단계 (MVP 분할)

### 🟢 1차 스프린트 — "핵심 2기능"이 동작하는 최소 제품

> 목표: 발명을 입력하면 → 진단 + 명세서/청구항 초안 + 할루시네이션 검증 표시.
> 이것만으로도 "동작하는 데모"가 되어 고객·투자자에게 보여줄 수 있다.

1. 프로젝트 세팅 (Next.js + TS + Tailwind + Prisma + PostgreSQL + Auth)
2. **발명 입력 폼** (STEP 1) + 발명 구조화 카드 (STEP 3)
3. **명세서·청구항 초안 생성** (STEP 18) — Anthropic API 서버 호출
4. **할루시네이션 검증** (STEP 19) — GREEN/YELLOW/RED 태깅 표시
5. Provenance Ledger 기본 기록 (모든 AI 호출 추적)
6. 법적 경계 문구 전역 표시 (등록 비보장·법률자문 아님)

### 🟡 2차 스프린트 — v4.0 MVP 1단계 완성

> v4.0 문서의 "MVP 1단계" 기능을 모두 채운다.

7. 선행기술 수동 입력형 **Evidence DB** (STEP 6)
8. **All Elements Matrix** (STEP 9) — 청구항 요소 ↔ 선행기술 1:1
9. **용어사전 + 안티센던트 검사** (STEP 16) — 룰 기반, 즉효
10. **Claim Ladder 생성** (STEP 14)
11. **Fallback Elements 표** (STEP 15)
12. **가상 OA 생성** (STEP 21) — 결합 동기 포함
13. **전문가 리뷰 화면** (STEP 24) + 승인 게이트 (STEP 24B)

### 🔵 이후 — 플랜 차별화 기능 (판매 본격화 단계)

- KIPRIS Plus / Google Patents 연동 (Pro)
- 효과데이터 프로토콜, SW/AI 적격성 Gate (Pro)
- 포트폴리오·FTO·경쟁사·Red Team·ROI (Enterprise)
- 구독·크레딧 과금, 조직관리, SSO, 모델 라우팅 (Enterprise)

### `CLAUDE.md` 템플릿 (프로젝트 루트에 저장)

```markdown
# 프로젝트: AI 특허출원 대시보드

## 무엇
발명 입력 → 등록 가능성 진단 + 명세서/청구항 초안 + 가상 OA를 만드는 SaaS.
상세 설계는 /docs/AI_patent_dashboard_workflow_v5_0.md 참조.

## 스택
- Next.js 14 App Router + TypeScript
- Tailwind CSS + shadcn/ui
- Prisma + PostgreSQL
- NextAuth
- Anthropic API (서버 사이드 전용)

## 절대 규칙
1. AI API 키·Agent 프롬프트를 클라이언트로 보내지 말 것. 모든 AI 호출은 서버에서.
2. 모든 AI 판단 함수는 LedgerRecord에 근거를 기록할 것 (recordLedger 래퍼 사용).
3. UI 어디에도 "등록 보장 / 법률 자문" 표현 금지. "초안·진단·참고" 로만.
4. 사용자 카드정보를 직접 다루지 말 것. 결제는 Stripe 위탁.
5. 발명정보는 영업비밀 — 테넌트(Organization)별로 데이터 격리.
6. 파일은 기능별 폴더로. 한 파일 300줄 넘으면 분리 제안.

## 코딩 컨벤션
- 타입은 명시적으로. any 금지.
- 서버 액션은 app/actions/ , API는 app/api/ , UI는 components/ .
- 커밋은 작게, 기능 단위로.

## 현재 작업 단계
1차 스프린트: 발명 입력 → 초안 생성 → 할루시네이션 검증.
```

### 효과적인 프롬프트 패턴

Claude Code에게 한 번에 "앱 전체 만들어줘"라고 하지 말 것.
**작은 단위로, 검증 가능하게** 지시한다.

| 나쁜 지시 | 좋은 지시 |
| --- | --- |
| "특허 앱 만들어줘" | "Prisma로 Invention, Claim, Evidence 테이블 스키마부터 만들어줘. WORKFLOW STEP 6의 Evidence 필드를 그대로 반영해." |
| "AI 기능 넣어줘" | "app/api/draft/route.ts 에 발명 구조화 카드를 받아 명세서 초안을 생성하는 서버 핸들러를 만들어줘. Anthropic API는 서버에서만 호출하고, 결과를 LedgerRecord에 기록해." |
| "UI 예쁘게" | "발명 입력 폼을 shadcn/ui로 만들어줘. STEP 1의 입력 항목을 섹션으로 그룹화하고, 하단에 '등록 비보장' 고지 배너를 고정 표시." |

권장 순서: **DB 스키마 → 서버 로직(AI 호출+원장) → API → UI** 순으로 쌓는다.
각 단계마다 "테스트 해보고 다음으로" 라고 명시.

### 주의사항

- Claude Code가 만든 **AI 호출 코드는 키 노출·프롬프트 인젝션**을 직접 점검하라.
- 생성된 코드를 그대로 배포하지 말고, 보안·법적 문구는 사람이 최종 확인.
- 큰 변경 전엔 git 커밋 — Claude Code가 되돌릴 수 있게.

## B-5. 개발 시 빠지기 쉬운 함정

1. **원장(Ledger)을 나중에 붙이기** → 처음부터 AI 호출 래퍼에 넣어라.
2. **AI 응답을 신뢰하고 그대로 출력** → 할루시네이션 검증(STEP 19)을 파이프라인 필수 단계로.
3. **토큰 비용 무시** → 발명 1건당 비용을 로깅해 가격 설계에 반영.
4. **법적 문구 누락** → 전역 레이아웃에 고지 컴포넌트를 박아 모든 화면에 노출.
5. **멀티테넌트 격리 미흡** → 다른 조직의 발명이 보이면 영업비밀 사고. 쿼리마다 org 필터.
