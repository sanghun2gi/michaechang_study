요약

5W1H 한 장 요약

Why

교란은 실제 피해를 준다. 하지만 RF 계측기 없이 “재밍이다”라고 말하면 과학적으로 무너진다. 그래서 탐지보다 반증과 한계 표기를 더 강하게 요구한다.

What

파일 요약이 아니라 파이프라인 소프트웨어 + 검증시험 + 후보 카탈로그 + 증거 묶음 + 최종보고서. 주장 강도는 증거등급 E0~E5로 제한된다.

Who

사람 연구자와 코딩 에이전트가 함께. 실행은 역할이 다른 12종 워커 프로세스가 나누어 병렬 수행한다.

Where

원시자료 rinex\Daily는 읽기 전용, 생성물은 결과 폴더에만. 외부 참조자료는 URL·해시와 함께 캐시한다.

When

“2021~2026”은 말일 뿐, 헤더와 실제 epoch로 확인한 기간이 진짜다. 게이트 P0~P12, 규모 R1~R5, 배리어 B1~B3가 순서를 강제한다.

How

인벤토리 → 품질 → 표준화 → 특징 → 기준선 → 탐지 → 공간 동조성 → 블라인드/외부검증 → 반증·분류 → 보고. 단계마다 완료 게이트가 붙는다.

Why

왜 이런 문서를 만들었는가

현실 문제

GNSS 신호는 지상에 도달할 때 매우 약하다. 그래서 비교적 작은 방해전파(재밍)나 위조신호(스푸핑)에도 수신 품질이 무너질 수 있다. 항공기 접근, 해상 항행, 정밀측위, 시각동기가 모두 영향을 받는다. 한국 주변에서도 GPS 수신장애 관련 항행경보·NOTAM이 발행된 사례가 있다.

왜 하필 CORS 30초 자료인가

  • 전국에 고정 설치되어 위치가 알려져 있다 → 위치가 흔들리면 그 자체가 이상신호
  • 장기간 연속 축적되어 있다 → 몇 년치 정상 분포를 만들 수 있다
  • 여러 관측소가 동시에 본다 → 한 대의 고장인지 지역 현상인지 구분할 수 있다

관측망 증거로는 강력하다. 다만 결정적 한계가 따라온다.

이 자료로 할 수 없는 것

RINEX는 RF 스펙트럼도, 수신기 내부 진단자료도 아니다. 방해신호의 전력·J/S·중심주파수·대역폭·변조방식·방향·송신원 위치를 측정했다고 말할 수 없다.

행위자·국가·기관 귀속은 불가능하다. 공식기관이 발표한 귀속을 인용할 때도 “당국 발표에 따르면”으로 한정하고 본 분석의 결론으로 올리지 않는다.

수신기 내부의 간섭완화 기능(AGC·notch filter)이 약한 간섭을 지워버릴 수 있다. 따라서 “안 보였다”는 “간섭이 없었다”가 아니라 “이 관측체계에서는 관측되지 않았다”이다.

30초 표본은 그보다 짧은 사건을 놓치거나 한두 epoch로만 남긴다. 시작·종료시각에는 항상 해상도 한계가 붙는다. 고정 CORS 30초 자료로 스푸핑을 확정하기는 특히 어려워, 결과 명칭을 spoofing_compatible(스푸핑과 양립 가능한 이상)로 제한한다.

왜 형식이 이렇게 빡빡한가

이 문서는 사람에게 주는 연구계획서가 아니라 코딩 에이전트에게 주는 실행 계약이다. 에이전트도 사람도 흔히 이런 실수를 한다.

  • 파일을 다 못 읽었는데 “분석 완료”라고 말한다
  • 확인하지 않은 관측소 수·기간·성능지표를 그럴듯하게 채운다
  • 파일럿 결과를 전체 결과처럼 보고한다
  • 이상치를 찾자마자 “재밍 탐지”라고 부른다

그래서 상태어를 강제하고, 모든 숫자를 claim ID로 역추적하게 하고, 게이트를 통과하지 못하면 다음 단계로 못 가게 막는다.

문서의 철학

후보 수가 줄어드는 것은 실패가 아니다. 자료장애·위성문제·수신기변경·전리층·현장환경으로 설명되는 후보를 제거하고도 남은 사건만 제한된 표현으로 제시한다.

최종 용도

SCI(E)급 논문 최대 3편(방법론 / 탐지·망 동조성 / 외부검증·사례)과 박사학위논문의 근거자료다. 다만 논문 편수는 사전 확정 목표가 아니다. 결과가 지지하지 않으면 병합·보류하고, 그래도 데이터 파이프라인은 완료로 인정한다.

분석 단위 계층

RawFile → Observation → Epoch → StationWindow → StationEvent → NetworkEvent → EventFamily

StationEvent는 한 관측소에서 시간적으로 이어지는 이상 구간, NetworkEvent는 허용 시차 안에서 여러 관측소가 비슷한 신호·대역·특징으로 이상한 묶음이다. AffectedObservationFootprint는 이상이 관측된 범위이지 간섭원 위치가 아니다. 모든 ID는 재실행·워커 수·파일 순서와 무관하게 같아야 한다.

상한

RINEX 단독 분석은 원칙적으로 E3을 넘지 않는다. NOTAM·항행경보 같은 advisory(예방적 경보)의 단순 시간중첩만으로는 E4를 줄 수 없다.

원인 분류 — 확정 라벨이 아니라 순위 있는 가설

jamming_like · spoofing_compatible · unintentional_rfi_possible · receiver_or_site_issue · satellite_or_product_issue · ionosphere_or_space_weather_possible · data_pipeline_issue · indeterminate

여기에 ICAO 용어와 맞추기 위한 보조 필드가 붙는다. 관측패턴은 band_selective / multi_band_common / temporally_unresolved / unassessable 중 하나이며, narrowband·barrage·chirp 같은 파형 이름은 스펙트럼 측정 없이 붙이지 않는다.

왜 W_VAL만 따로 떼어 놓는가

“공식 사건이 언제 있었는지” 아는 상태로 임계값을 고르면 그건 탐지가 아니라 사후 맞추기다. 그래서 공식 사건정보를 다루는 역할은 별도 프로세스·별도 출력 경로로 격리하고, 블라인드 산출물이 동결된 뒤에만 작동시킨다.

어떤 자료를 읽는가

  • 관측파일(RINEX OBS) — 2/3/4 버전, Hatanaka(.crx/.d), .gz, .Z, .zip 등. 파일명으로 유형을 확정하지 말고 헤더로 판별한다.
  • 항법자료 — 로컬 NAV, BRDC, SP3(정밀궤도), CLK. 없으면 고도각·잔차 계산이 제한된다.
  • 외부 참조 — IGS GIM(IONEX), GFZ Kp, Kyoto WDC Dst, NOAA SWPC, IGS MGEX의 시간유효 GLONASS 채널 metadata.
  • 공식 사건자료 — 정부·항공교통·해양(NAVAREA XI)·ICAO APAC 1차 출처, NOTAM, AIS 위치이상 집계. 각각 source_tier와 advisory/confirmed를 구분한다.

외부에서 받은 것은 URL·취득시각·해시를 남기고 비공식 출처는 쓰지 않는다.

공간 범위 주의점

  • 한국 관측소는 QZSS(J) 가시성이 높고 KASS 운용 후 SBAS(S) 관측이 있을 수 있다 → 존재를 인벤토리에서 확인하고 포함·제외 정책을 설정에 명시
  • 서해·동해 도서 관측소는 공간통계에서 이웃이 없어 고립될 수 있다 → 먼 내륙 관측소와 강제 연결하지 말고 spatial_isolate=true로 기록하고 제외 사실을 보고
When

언제의 자료를, 어떤 순서로

분석 대상 기간

  • 사용자는 “2021~2026년”이라고 말했지만 그대로 믿지 않는다. 헤더의 TIME OF FIRST/LAST OBS와 실제 epoch로 확인한다.
  • analysis_cutoff_utc = min(configured_end_utc, latest_valid_observation_epoch)로 고정한다.
  • 2026년이 완전한 1년임이 증명되지 않으면 반드시 2026 YTD로 표기한다.
  • 연도 간 비교는 동일 DOY 범위 또는 유효 station-day로 노출량을 표준화한다.

시간 표기와 함정

RINEX의 time system은 GPS time / UTC / GLONASS time / BDT / GST가 섞일 수 있다. 내부 기준시각을 하나로 통일하고 leap second 처리를 검증한 뒤 UTC와 KST 열을 만든다. 모든 원시시각에 그냥 9시간을 더하지 말라고 명시되어 있다. 관측소 간 1 epoch 차이는 “30초 해상도 범위의 불확실성”이지 전파 이동시간이 아니다.

R5확인된 전체기간·전체망전량 실행, manifest reconciliation
사후 튜닝 금지

R4에서 동결한 임계값을 R5 결과를 보고 다시 바꾸지 않는다. 민감도 결과 중 유리한 값만 골라 쓰는 것도 금지된다.

③ 병렬 배리어 B1~B3 — 워커가 넘을 수 없는 벽

B1

인벤토리·품질이 끝나기 전에 특징추출을 파일럿 범위 밖으로 확대 금지

B2

기준선이 동결되기 전에 탐지 금지. 워커마다 다른 기준선을 쓰면 후보가 워커 수에 의존하게 된다

B3

블라인드 후보가 동결되기 전에 공식 사건자료 사용 금지

배리어 통과 선언은 orchestrator만 한다.

How

어떻게 수행하는가

파이프라인 · 병렬 실행 · 품질보증

분석 파이프라인 11단계

단계 0

환경·기존 자산 감사

기존 코드·문서·사건목록·관측소 메타데이터를 찾아 ① 그대로 재사용 ② 수정 후 사용 ③ 제외 로 분류한다. Python 패키지와 GFZRNX·Hatanaka 도구 유무를 기록한다.

→ project_inventory.csv · reports/00 · logs/environment.txt
단계 1

헤더 중심 전수 인벤토리

본문을 다 읽지 않고 모든 파일의 헤더만 훑는다. 상대경로·크기·압축·RINEX 버전·관측소 ID·첫/마지막 epoch·수신기/안테나·관측코드·위성군(G/R/E/C/J/S/I)·예상 대비 실제 epoch 수·중복·손상 여부를 기록한다.

→ rinex_file_inventory.parquet · station_year_coverage.csv · observation_code_matrix.csv
단계 2

데이터 품질 게이트

관측소×일자 단위로 관측률, 최장 공백, 위성 수 분포, S 관측값·LLI 유무, 이중주파수 가능 여부를 계산하고 Q0~Q4 등급을 매긴다. Q0~Q1은 삭제하거나 억지로 보정하지 말고 제외 사유를 남긴다. SNR이 없는 관측소는 별도 특징세트로 다루고 SNR을 추정 생성하지 않는다.

단계 3

항법자료·시간·좌표 표준화

궤도자료가 없으면 해당 특징은 not_computed로 남기고 가능한 분석만 진행한다. GLONASS 채널번호는 헤더 → 로컬 항법자료 → IGS MGEX 시간유효 metadata 순으로 해결하고, 현재 시점 PRN 정적 룩업은 금지한다. Kp는 3시간, Dst는 1시간 해상도라 30초 사건과 직접 비교할 수 없음을 기록한다.

단계 4

재현가능한 특징 추출 (핵심)

가용성·tracking — 위성 수, 결측률, 소실·재획득, gap, LLI bit 0/1 분리, cycle slip 후보.
신호강도 — Sxx가 dB-Hz로 확인될 때만 사용. S1C와 S1W는 같은 family 안에서만 비교하고 C1C(의사거리)와 섞지 않는다. RINEX 2의 S1은 임의 매핑 없이 legacy_ambiguous로 격리.
대역·위성군 차분 — 대역별 Tracking Ratio(L1만 죽고 L2/L5는 살아있는가 vs 전 대역 동시 저하), 대역 간 SNR 격차, CDMA(GPS) vs FDMA(GLONASS) 차이, ROTI.

단계 5

정상 기준선 구축

“전체기간 평균 하나”로 만들면 안 된다. 관측소 × metadata regime × 위성군 × 정확 관측코드 × 실제 주파수 × 고도각 구간 × 시간대·계절로 나눈다. MAD가 0일 때 임의의 작은 값으로 큰 z를 만들지 말고 정해진 fallback 순서를 따르며 사용률을 보고한다. 미래 데이터로 과거 기준선을 학습하는 누수를 금지한다.

단계 6

다중 검출기 이상탐지

독립 특징군 5개 — signal-strength · tracking · measurement-consistency · solution · availability. 기본 후보 규칙은 “같은 시간창에서 최소 두 개의 독립 특징군이 이상”이다. ROTI는 검출기가 아니라 반증 단계의 대조 지표다. 다중검정을 고려해 FDR 또는 경험적 오경보율을 보고한다.

단계 7

다중 관측소 시공간 동조성

“동시 이상 관측소 수”를 세는 데서 멈추지 않는다. Moran’s I·Geary’s C + 순열검정, 가중행렬 최소 3개 대안 비교(80 km는 표준이 아니라 50/80/120 km 민감도 후보), 거리–동조성과 semivariogram은 기술통계로만 보고. 전파원 위치를 추정했다고 표현하지 않는다. 지도에는 “이상 관측망 범위”만 표시한다.

단계 8

블라인드 탐지와 외부검증 분리

트랙 A 공식 사건일을 보지 않고 기준선·후보를 확정하고 동결(생성시각·코드 버전·설정 해시 기록) → 트랙 B 동결 후에만 공식 사건표와 대조(언론기사는 탐색 보조, 최종 근거는 1차 출처) → 트랙 C 유사 지자기 활동 수준까지 맞춘 matched control과 비교. 공식 사건이 관측망 밖이거나 시공간이 모호하면 “검출 실패”가 아니라 평가불가다.

단계 9

반증 엔진과 분류

상위 후보는 전부 ① 수신기·안테나·현장 ② 위성·항법제품 ③ 전리층·우주기상 ④ 기상 ⑤ 데이터 파이프라인 대안설명을 거친다. 상태는 hard_refuted / softly_explained / not_refuted / untestable / conflicting_evidence. untestable은 긍정 증거가 아니다. 후보가 단계마다 몇 개씩 줄어드는지 funnel로 기록한다.

단계 10·11

확대와 시험

파일럿 → 확대 → 전체로 가되 모든 표·그림에 pilot/expanded/full 범위를 표기한다. 시험에는 압축형식, 윤년·DOY·leap second, LLI bit, GLONASS FDMA, BDS B1I ≠ B1C/L1 분리, L2C와 L2W 분리, 합성 사건 탐지, 정상 자료 오경보, 결정적 재실행, 중단 후 resume, 실제 파일 수동 검산이 포함된다.

병렬화의 축은 셋이다. 데이터 병렬(같은 일을 다른 자료에 — 처리량의 대부분), 역할 병렬(특징추출 중에 외부자료 다운로드·그림 생성), 구현 병렬(코드 작성 분담).

초보자가 반드시 걸리는 두 함정

함정 1 · 경계(halo)

일자 단위로 나누면 자정을 걸친 현상이 잘린다. 창 특징은 앞뒤로 읽기 패딩을 두되 쓰기는 자기 구간만. ROTI arc는 앞뒤 30분 포함해 연속성 판정. 사건은 경계에 닿으면 boundary_open으로 표시하고 단일 reduce에서 병합.

함정 2 · 분산 집계

count·sum·min·max·히스토그램은 합산되지만 median·MAD·분위수는 파티션별로 구해 평균낼 수 없다. 기준선이 바로 이걸 쓴다. → 2-pass(정확·느림) 또는 t-digest류 스케치(빠름·근사, 오차 보고 필수).

실행 명령 예시

cli plan   --config config/analysis.yaml --scale r3 --shards 16

cli worker --role W_INV  --workers 6      # IO 바운드
cli worker --role W_QC   --workers 6
cli worker --role W_EXT  --workers 2      # 동시 진행 가능
cli barrier declare --name b1_inventory_quality_complete

cli worker --role W_FEAT --workers 8      # CPU 바운드
cli worker --role W_BASE --workers 4
cli barrier declare --name b2_baseline_frozen --evidence <HASH>

cli worker --role W_DET  --workers 8
cli worker --role W_NET  --workers 2
cli reduce --stage network_events         # 경계 재병합

cli freeze-blind
cli barrier declare --name b3_blind_freeze_before_official
cli worker --role W_VAL --workers 1       # 별도 프로세스
순서 규칙

R1·R2는 워커 1개 직렬로 정확성을 확보하고, R3에서 큐·배리어·샤딩을 도입해 불변성 시험(--shards 1/4/16, --workers 1/N의 결과 해시가 같은가)을 통과한 뒤에만 워커를 늘린다. 워커 수를 늘려 결과가 달라지면 성능 문제가 아니라 정확성 결함이다.

코드 작성을 여러 명이 나눌 때

  1. 인터페이스 먼저 동결(스키마·설정·큐 스키마·ID 규칙) — 끝나기 전엔 병렬 구현 시작 금지
  2. 골든 픽스처(작은 실제 파일 + 기대 출력) 먼저 만들기
  3. 모듈 파일 단위로 소유권 분배 (같은 파일 동시 수정 금지)
  4. 병합은 하위 의존(파서·시간·기하)부터 상위(평가·보고)로

시작

처음 시작하는 사람을 위한 5단계

01

뼈대부터 읽는다

원문의 “가장 중요한 과학적 제한”과 39.2절 단계별 표만 먼저 읽는다. 이 둘이 문서의 뼈대다.

02

환경을 확인한다

원시자료 폴더에 읽기 전용으로 접근되는지, 결과 폴더를 만들 수 있는지, 디스크 여유가 있는지.

03

워커 1개로 R1을 끝까지

파일 하나. 헤더·시간계·관측코드가 예상과 맞는지가 전부다.

04

R2 → R3까지 간 뒤 병렬 도입

하루치 end-to-end, 그다음 3~10 관측소. 병렬(큐·배리어·샤딩)은 여기서 처음 켠다.

05

탐지보다 반증에 시간을 쓴다

후보가 나오기 시작하면 반증이 본 게임이다. 남는 후보가 적은 것이 정상이다.
